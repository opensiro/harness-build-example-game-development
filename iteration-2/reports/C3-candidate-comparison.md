## Scope, licensing, and comparisons

No upstream source code is proposed to be copied; an independently written Python 3.12 standard-library implementation is permitted, with structural influence attributed to pinned source links. Upstream licenses were **not used as authority for literal code transfer**. If copying becomes necessary, separately review the exact pinned upstream license first; no such copy is planned. The source-level construction experiment does not rank candidate runtime quality, game win rate, or model ability.

| Construction route | Advantages | Costs / uncertainty |
|---|---|---|
| **Existing runner only (NO_ADAPTATION)** | Keeps original legal-action and settlement guarantees; simplest | Does not satisfy preregistered explicit R2/R3/R4 contextual operating loop; cannot count existing source alone as new C4 completion |
| **Episode-local typed public-feedback history** (BALROG / BabyAI) | Feeds actual settled results into next policy step and resets per episode | Must rigorously separate hidden authoritative state, tentative model intentions and settled receipts |
| **Pluggable session decision envelope with policy-private strategic note** (Dexto) | Lets external real AI express changing goals/strategy without a model runtime dependency | Must validate incoming metadata sizes/types, keep decision source incapable of environment mutation, avoid treating free-text notes as trusted authority |
| **Bounded sliding context / repetition guard** (agent-runtime) | Prevents unbounded growth or repeated fruitless generation sequences and is standard-library only | A fixed event-window is **not** a semantic summary or a token-budget guarantee; resource caps don't ensure end-to-end I/O timeout |
| **Self-modifying persistent harness / neural recurrent policy** (Continual Harness / Genesis / BabyAI) | More powerful cross-task adaptation in principle | Unneeded provider, framework, model/storage or safety infrastructure; unverified runtime properties for this experiment |

## Evidence limitations / next mandatory sequence

- The comparison relies on new Cognee lexical leads and **actual** pinned canonical assessment + upstream file reads. No full-body Cognee indexing was performed; candidate coverage is consequently limited to six function sections. Despite this, relevant *specific* R2/R3/R5 and context-pressure evidence is in returned first-pass function chunks. Broader full-body discovery could change shortlist and cannot be ruled out.
- Source file reads establish design inspiration, **not operational correctness** of newly authored code and not a successful game evaluation.
- No architecture is **selected in this comparison**. The subsequent **separate C3 decision commit must cite this comparison's SHA**, specify exact chosen/rejected components and per-mechanism `discovery_contribution`. Implementation must follow that decision, never precede it.
